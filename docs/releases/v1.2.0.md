## Packages

The same package types as 1.0.0:

| File | What it is |
|---|---|
| `StudyBoard-1.2.0-windows-AMD64.exe` | Windows installer (NSIS) |
| `StudyBoard-1.2.0-windows-AMD64.zip` | Windows portable ZIP: unpack anywhere, run `bin\studyapp.exe` |
| `StudyBoard-1.2.0-linux-x86_64.AppImage` | Linux AppImage |
| `StudyBoard-1.2.0-linux-x86_64.tar.gz` | Linux archive: unpack anywhere, run `bin/studyboard` |
| `StudyBoard-1.2.0-macos-arm64.dmg` | macOS disk image |

The packages are built by the release workflow from the tag. Their sizes and SHA-256
checksums exist only then: they are in `SHA256SUMS.txt` next to the packages and are
recorded in [RELEASE.md, Release records](../RELEASE.md#release-records) after
publication.

**Upgrading from 1.0.0.** The Windows installer uses the same folder as 1.0.0 and replaces
an installed 1.0.0 (as any newer installer does). To keep 1.0.0 installed, use the portable
ZIP. Both versions share the same settings (window layout, tool settings, recent
workspaces).

**Workspaces.** 1.2 has no database schema change: workspaces opened or created with 1.2.0
still open normally in 1.0.0, and the other way round. Text boxes with a non-default font
size (new in 1.2) are shown at the default size by 1.0.0. Installing, upgrading or
uninstalling never touches workspaces.

## What is new since 1.0.0

### Command console and PDF content search (1.2-CMD-01)

* A **command console** (View ▸ Command Console, Ctrl+Shift+C): type StudyBoard commands
  instead of clicking — `list notebooks/sections/pages`, `open page <title>`, `go <n>`,
  `search <text>`, `workspace info`, `import pdf "<path>"`, `export page pdf|png|svg [path]`,
  `export section pdf [path]`, `undo`, `redo`, `diagnostics`, `history`, `clear`, `help`.
* **Help** for every command with examples; **autocomplete** of command names (Tab);
  **history** of the session (↑ / ↓).
* **`pdf search "<text>"`** searches the text *inside* the imported PDFs: case-insensitive
  (also for accented, Greek and Cyrillic letters), phrases across line breaks, results
  grouped by PDF with page number and context; `go <n>` or a click opens the page.
  `cancel` stops a running search.
* It is **not a shell**: only registered StudyBoard commands run; anything else is
  "Unknown command". Nothing typed reaches the operating system.
* Details: [COMMAND_CONSOLE.md](../COMMAND_CONSOLE.md), [PDF_WORKER.md §23](../PDF_WORKER.md#23-text-extraction).

### Batch PDF export (1.2-CMD-03)

* **`export notebook pdf <folder>`** writes one PDF per section of the current notebook —
  the notebook of the open page — into an existing folder, in notebook order. Each file is
  exactly what `export section pdf` writes for that section.
* It runs **in the background** (design D56): the window, the canvas and the console stay
  usable, each section is reported in the console when it has been written, and the status
  bar and `diagnostics` show the export. It exports the notebook as it was when the command
  was entered; later edits are in the workspace and not in the files.
* **Existing files are never replaced**: if a target file exists, nothing is exported. A
  section that cannot be written does not stop the others; a section without pages is
  skipped.
* **`cancel`**, closing the workspace, opening another one or quitting stops it before its
  next page; the sections already written stay and no partial file is left.
* File names come from the section titles, made safe for every platform and numbered when
  two are equal. Details and limits:
  [COMMAND_CONSOLE.md §10](../COMMAND_CONSOLE.md#10-batch-operations).

### PDFs read in an isolated worker process (1.2-PDF-01, 1.2-PDF-02)

* Imported PDFs are inspected — and, for PDF search, their text extracted — by a separate
  short-lived `studyapp --pdf-worker` process (design D53). A damaged or hostile PDF that
  crashes or hangs the PDF reader fails only that import or search; StudyBoard keeps
  running, and closing a workspace stops a running worker.
* `studyapp --self-test` checks the worker on every installation.

### Text (1.2-TXT-01, 1.2-TXT-02)

* **Font size per text box**: Tools ▸ Text Size (and the text tool's style button) with
  presets from 12 to 72, for new boxes, the box being edited or the selected boxes; one undo
  step; exports use the box's size.
* Resizing a text box shows the text laid out for the new width instead of a stretched
  image.

### Imports (1.2-IMP-01)

* An image or PDF import that finishes after you moved to another page no longer pulls you
  back: the image is placed on the page it was started from, and a PDF opens only if you
  are still on that page (otherwise it appears in the tree).
* Files of imports that were abandoned (workspace closed during an import) are cleaned up at
  once instead of staying in the workspace's `temporary/` folder.

### Under the hood

* Process messaging infrastructure through IPCFileLab (D52), used by the PDF worker.
* Maintenance operations measured on 1 GB and 5 GB workspaces (1.2-PERF-01); the findings
  are listed under "Known limitations", no behaviour changed.
* CI and packaging: CI and packages run for `dev/**` and for release lines (`release/**`);
  CMake and linuxdeploy are pinned and verified by SHA-256 (1.2-CI-01, 1.2-REL-01,
  1.2-REL-02, 1.2-REL-03).
* The version shown to users can carry a label for development builds (`1.2.0-dev`); the
  release reports `1.2.0`, without a label.

Everything from 1.0.0 is unchanged and still included: notebooks, sections and pages, pen,
highlighter, shapes, text and images, PDF import and annotation, the planner (courses,
projects, tasks, Today/Tasks/Week views), full-text search, exports and printing, bundles,
continuous saving and backups.

## Changes since the development build 1.2.0-dev

For those who tried [1.2.0-dev](v1.2.0-dev.md), a development build that was not a release:

* **New:** batch PDF export, `export notebook pdf <folder>` (above). `cancel` now stops a
  running batch export as well as a PDF search.
* **Version:** `1.2.0` instead of `1.2.0-dev` everywhere it is shown, and in the package
  and installer names.
* **CI and packaging** also run on pushes to release lines (`release/**`).
* **Moved to version 2.0:** highlighting PDF search matches on the page (1.2-CMD-02) and a
  persisted PDF text index (1.2-PDF-03), which the development build's notes listed as
  planned follow-ups ([ROADMAP.md, Version 2.0](../ROADMAP.md#version-20-not-started-dev20)).

Nothing else changed in the features that build contained.

## Testing

* CI runs on the development line, on `main` and on the release line: formatting and
  module boundaries, clang-tidy, Qt-free core tests on Windows, Linux and macOS, ASan +
  UBSan, and the full test suite (including GUI tests on the offscreen platform) on all
  three platforms.
* The release candidate has 582 tests in the Qt-free suites and 588 in the full suite as
  built on Windows; a few tests exist on one platform only, so the full count differs
  slightly between platforms ([TESTING.md](../TESTING.md)).
* The packages are built and smoke-tested on clean runners without Qt or a compiler: the
  Windows installer is installed, self-tested and uninstalled; the ZIP, AppImage, tar.gz and
  DMG run `--self-test` (which includes the PDF worker and PDF text search) and must report
  the version in their file name.
* The runs for the tagged commit are recorded in
  [RELEASE.md, Release records](../RELEASE.md#release-records) after publication.

## Known limitations

* **Unsigned packages:** Windows SmartScreen and macOS Gatekeeper warn on first start
  ([RELEASE.md](../RELEASE.md#signing)).
* **PDF search:** matches are not highlighted on the page (PDF pages are drawn as images);
  no OCR, so scanned PDFs have no searchable text; text beyond 64 KiB per page or 8 MiB per
  PDF is not searched; the text cache lasts for the session, so the first search after
  opening a workspace reads each PDF again.
* **Console:** command arguments (paths, titles) are not autocompleted; the history is not
  kept between sessions.
* **Batch PDF export:** only PDF, only the notebook of the open page, only into an existing
  folder given with its full path, one export at a time. The length of the whole path is
  not checked; section names that differ only in the case of non-ASCII letters or in
  Unicode normalisation are not numbered; a file that appears between the last check and
  the moment a PDF is put in place is replaced; a killed process or a power failure can
  leave a temporary file in the folder; showing other PDF pages can be slower while a
  section with imported PDF pages is exported
  ([COMMAND_CONSOLE.md §10.1](../COMMAND_CONSOLE.md#101-export-notebook-pdf-folder),
  "Limits"). The export thread's code in `ui` is tested on all three platforms but is not
  covered by a sanitizer build, which is Qt-free ([TESTING.md](../TESTING.md)).
* **Other exports:** `export page …`, `export section pdf`, File ▸ Export and printing
  still run on the GUI thread.
* **Large workspaces:** Check Workspace, bundle export/open/import and Save a Copy freeze the
  window for several seconds per GB of assets; a workspace whose bundle would exceed 4 GiB
  cannot be exported (it fails after the attempt).
* **Platforms:** macOS is built and smoke-tested by CI only; no pen/tablet hardware has been
  tested. Everything listed under "Known limitations" of 1.0.0 in the [README](../../README.md)
  still applies.
